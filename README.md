# MeshCore decoder & receiver

Две утилиты для разбора пакетов сети [MeshCore](https://docs.meshcore.io/), принятых SDR-приёмником:

| Файл | Что делает |
|---|---|
| `meshcore_reader_json.py` | Приёмник: получает пакеты от SDRangel по UDP, разбирает и расшифровывает, показывает в консоли и пишет в лог по фильтрам. |
| `meshcore_decoder.pyw` | Подробный разбор одного пакета: окно (GUI) или командная строка. |
| `meshcore_proto.py` | Общий модуль: формат пакетов, ключи, расшифровка. Должен лежать в одной папке с программами. |

Dragon_Knight при поддержке Claude (Anthropic)

## Что нужно

- **SDR-приёмник**, который поддерживает SDRangel, например RTL-SDR.
- **[SDRangel](https://github.com/f4exb/sdrangel/releases)** с плагином MeshCore — он демодулирует LoRa и отдаёт пакеты по UDP.
- **Python 3.8+** и библиотека `cryptography` версии 40 или новее:
  ```
  pip install cryptography
  ```
  Без неё разбираются только открытые пакеты. Вместо неё можно поставить `pycryptodome`, но тогда будет работать только расшифровка каналов: подписи ADVERT и личные сообщения (ECDH) не проверяются.
- Для окна decoder нужен `tkinter` (в Windows идёт вместе с Python).

## Настройка SDRangel

1. Скачайте и установите SDRangel со страницы [releases](https://github.com/f4exb/sdrangel/releases), подключите приёмник.
2. Добавьте канал с плагином MeshCore и выставьте параметры радио, как у узлов вашего региона: частоту, полосу (BW), SF и CR.
3. Включите в плагине отправку пакетов по UDP на адрес компьютера с приёмником и порт **4404** (или другой, тогда запускайте reader с `--port`).
4. **Ключи каналов в плагин вводить не нужно.** Расшифровывает reader сам, ключи задаются в его настройках.

Reader ждёт JSON с полями `lora.payload_hex` (пакет целиком), `lora.header_crc`, `lora.payload_crc` (`ok` / `err` / `n/a`), `rf.snr_db`, `rf.signal_db` (RSSI), `rf.spreading_factor`. Мусор до и после JSON в UDP-пакете отбрасывается.

## Быстрый старт

```
python meshcore_reader_json.py
```

Свой канал и свой ключ для личных сообщений:

```
python meshcore_reader_json.py -k "#mychannel" -k "work:00112233445566778899aabbccddeeff" --private-key <hex>
```

Разобрать один пакет (без пакета откроется окно):

```
python meshcore_decoder.pyw 1902b07f37f3a57f... -k 00000000000000000000000000000000
python meshcore_decoder.pyw --keys-file mesh_contacts.txt --private-key <hex>
```

## Как работает reader

1. **Приём.** Из UDP-пакета извлекается JSON. Пакет с ошибкой CRC по умолчанию не разбирается, вместо него печатается серая строка-заметка (см. `BAD_PACKET_MODE`).
2. **Заголовок.** Тип маршрута, тип payload, версия, transport codes, path (через какие узлы прошёл пакет). Битый, обрезанный или нестандартный заголовок даёт тип `raw` с причиной.
3. **Payload** разбирается по своему типу (таблица ниже).
4. **Расшифровка.**
   - **Каналы (GRP_TXT, GRP_DATA).** В пакете есть 1-байтовый хэш канала. Пробуются все известные ключи с этим хэшем, верный ключ подтверждается MAC.
   - **Личные пакеты (REQ, RESPONSE, TXT_MSG, PATH, ANON_REQ).** Шифруются общим секретом двух узлов (ECDH). Расшифровать можно, только если один из узлов — вы: нужен свой приватный ключ (`PRIVATE_KEY`) и публичный ключ собеседника. Ключи собеседников reader собирает сам из ADVERT и ANON_REQ.
5. **Тип для фильтров** — по типу payload. Удалась ли расшифровка, хранится отдельно (`decrypted`).
6. **Фильтры и лог.** Пакет показывается, если прошёл `SHOW_RULES` и не попал в `HIDE_RULES`. В лог он пишется, если совпало правило из `LOG_RULES`. Экран и лог независимы.
7. **Контакты.** Новые публичные ключи узлов сохраняются в `mesh_contacts.txt` и загружаются при следующем запуске.

## Типы пакетов

Тип записан в заголовке пакета. Столбец «Фильтр» — значение `"type"` в правилах reader и название плашки в выводе.

| Код | Тип | Фильтр | Что это |
|---|---|---|---|
| 0x00 | REQ | `direct` | Запрос к узлу: статус, телеметрия, соседи, права доступа. Шифрованный. |
| 0x01 | RESPONSE | `direct` | Ответ на REQ или на вход (ANON_REQ). Шифрованный. |
| 0x02 | TXT_MSG | `direct` | Личное текстовое сообщение одному узлу. Шифрованное. Бывает обычным, подписанным или командой CLI для репитера. |
| 0x03 | ACK | `ack` | Подтверждение доставки: 4 байта контрольной суммы. Открытый. |
| 0x04 | ADVERT | `advert` | Объявление узла: публичный ключ, время, подпись, тип узла, имя, координаты. Открытый, подписанный. |
| 0x05 | GRP_TXT | `message` | Текст в канал (Public, #хэштег-каналы, приватные). Шифруется ключом канала, внутри «Имя: сообщение». |
| 0x06 | GRP_DATA | `data` | Двоичные данные в канал для сторонних приложений. Стандарт: тип данных + длина + данные. Другой формат показывается как есть (`non-standard`). |
| 0x07 | ANON_REQ | `anon` | Запрос от незнакомого узла: его публичный ключ открыт, содержимое шифровано. Вход на репитер или в комнату по паролю. |
| 0x08 | PATH | `direct` | Возврат найденного маршрута, чтобы дальше слать напрямую. Шифрованный, может нести ACK. |
| 0x09 | TRACE | `trace` | Трассировка по списку репитеров с SNR на каждом хопе. Открытый. |
| 0x0A | MULTIPART | `multipart` | Часть пакета, разбитого на несколько. |
| 0x0B | CONTROL | `control` | Служебные: поиск узлов рядом (DISCOVER_REQ / DISCOVER_RESP). Открытый. |
| 0x0C–0x0E | зарезервированы | `raw` | Не используются протоколом. |
| 0x0F | RAW_CUSTOM | `custom` | Произвольные данные своих приложений. |
| — | — | `raw` | Пакет не разобран: битый или обрезанный заголовок, payload короче минимума, зарезервированный тип, версия выше v1. Причина — в строке `Reason`. |

Сокращения: GRP — group (канал), TXT — text, MSG — message.

**Тип маршрута** (строка под шапкой):
- FLOOD — пакет пересылают все репитеры, path копит пройденные узлы;
- DIRECT — пакет идёт по известному пути;
- TRANSPORT_FLOOD / TRANSPORT_DIRECT — то же с кодами, ограничивающими регион.

У шифрованного пакета без подходящего ключа в строке маршрута стоит `🔒 no key`.

## Ключи

Один формат для `KEYS`, `-k`, файла `--keys-file` (по ключу на строку, `//` — комментарий) и поля ключей в окне decoder:

| Запись | Что это |
|---|---|
| `public` | Публичный канал, добавляется всегда (`--no-public` отключает). |
| `#name` | Хэштег-канал, ключ = SHA256("#name")[:16]. Имя приводится к нижнему регистру. |
| `<32 hex>` | Ключ канала без имени (16 байт). В выводе канал называется `key`. |
| `name:<32 hex>` | Ключ канала с именем. |
| `<64 hex>`, `name:<64 hex>` | Общий секрет двух узлов (32 байта) для личных сообщений. |
| `pub:[name:]<64 hex>` | Публичный ключ контакта для ECDH. |
| `prv:<hex>` | Свой приватный ключ: 64 байта из экспорта приложения MeshCore или 32 байта seed. |

Вместо hex можно писать base64. В hex допустимы разделители `:`, `-`, пробел и префикс `0x`.

## Настройки reader

Задаются в начале `meshcore_reader_json.py`.

| Настройка | По умолчанию | Что делает |
|---|---|---|
| `UDP_IP`, `UDP_PORT` | `0.0.0.0`, `4404` | Адрес и порт приёма (`--port`). |
| `RCVBUF_SIZE` | 1 МБ | Буфер сокета, чтобы не терять пакеты при плотном потоке. |
| `BAD_PACKET_MODE` | `skip` | Пакеты с ошибкой CRC: `skip` — строка-заметка, `silent` — молча отбросить, `parse` — разобрать с пометкой `BAD` (`--bad`). |
| `SHOW_DEBUG_JSON` | `False` | Печатать исходный JSON (`--debug`). |
| `SEPARATOR_WIDTH` | `60` | Длина линии между пакетами. |
| `KEYS` | список #каналов | Ключи для расшифровки (формат выше). |
| `PRIVATE_KEY` | пусто | Свой приватный ключ для ECDH (`--private-key`). |
| `SAVE_CONTACTS`, `CONTACTS_FILE` | `True`, `mesh_contacts.txt` | Сохранять и загружать ключи узлов из эфира (`--contacts-file`, `--no-contacts`). |
| `SHOW_RULES` | пусто | Что показывать; пусто — всё. |
| `HIDE_RULES` | — | Что скрывать, даже если прошло `SHOW_RULES`. |
| `LOG_ENABLED`, `LOG_FILE` | `True`, `mesh_log.txt` | Лог (`--no-log`, `--log-file`). |
| `LOG_RULES` | — | Что писать в лог; пусто — лог выключен. |
| `LOG_ONLY_SHOWN` | `False` | Писать в лог только то, что прошло фильтр экрана. |

### Правила фильтров

Правило — словарь. Условия внутри правила объединяются по И, правила в списке — по ИЛИ. Любое условие можно не указывать, пустое правило `{}` совпадает с любым пакетом.

| Условие | Пример | Смысл |
|---|---|---|
| `type` | `"message"`, `["ack", "trace"]` | Тип пакета (таблица выше). |
| `decrypted` | `True` / `False` | Расшифрован или нет ключа. Только для `message`, `data`, `direct`, `anon`. |
| `channel` | `["public", "#moscow", "37"]` | Имя канала или его хэш в hex. Только для `message` и `data`; хэш виден и без ключа. |
| `route` | `"flood"`, `"direct"`, `"transport_flood"`, `"transport_direct"` | Тип маршрута. `flood` и `direct` включают и transport-варианты. |
| `hops` | `(0, 2)`, `(3, None)`, `2` | Число хопов, границы включительно. |
| `snr` | `(5, None)` | SNR в dB. |
| `rssi` | `(None, -110)` | RSSI в dB. |
| `match` | `"dragon"`, `"привет\|hello"` | Регулярное выражение без учёта регистра по имени узла, отправителю и тексту. |

Примеры:

```python
SHOW_RULES = [{"type": ["message", "advert"]}]                        # только сообщения и объявления
HIDE_RULES = [{"type": ["ack", "multipart"]}, {"decrypted": False}]   # без ACK и без пакетов без ключа
LOG_RULES = [
    {"type": "message", "match": "dragon"},                           # упоминания в чатах
    {"type": ["message", "data"], "channel": ["37"]},                 # всё по каналу с хэшем 37
    {"rssi": (None, -115)},                                           # самые слабые сигналы
]
```

## Командная строка

**Reader:** `--port`, `-k/--key SPEC` (можно несколько раз), `--keys-file FILE`, `--private-key HEX`, `--no-public`, `--contacts-file FILE`, `--no-contacts`, `--debug`, `--log-file FILE`, `--no-log`, `--no-filter` (отключить `SHOW_RULES` и `HIDE_RULES`), `--bad {skip,silent,parse}`, `--version`.

**Decoder:** `[пакет в hex или base64]`, `-k/--key SPEC`, `--keys-file FILE`, `--private-key HEX`, `--no-public`, `--version`. Без пакета открывается окно, ключи из командной строки подставляются в его поля. Строка `Filter type` показывает, каким типом пакет увидит reader.

## Файлы, которые создаёт reader

- `mesh_contacts.txt` — ключи узлов (`pub:имя:<hex>`). Подходит decoder'у как `--keys-file`.
- `mesh_log.txt` — лог по `LOG_RULES`.
